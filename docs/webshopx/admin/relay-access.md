# Relay 公网访问

Relay 模式用于在不直接暴露 Minecraft 服务器 Web 端口的情况下，为 WebShopX 提供公网访问入口。本页只说明服主可见的使用流程；Relay 服务端属于闭源服务，不在本文档中介绍其部署与内部实现。

## 1. 适用场景

- 没有固定公网 IP，或不方便配置端口映射。
- 希望通过统一入口访问 WebShopX。
- 不准备自行维护 Nginx、证书和公网转发。

Relay 是 `internal`、`external` 之外的第三种运行模式。

## 2. 推荐的设备授权流程

1. 以拥有 `webshop.admin` 权限的管理员身份进入游戏。
2. 执行 `/ws mode setup relay`。
3. 点击游戏内返回的安全授权链接。
4. 在 Relay 页面登录或注册，并确认授权当前服务器。
5. 回到游戏等待授权完成。授权请求约 10 分钟后过期。
6. 执行 `/ws mode switch relay`。
7. 执行 `/ws home`，验证服务器主页可以打开。

授权链接只发送给游戏内管理员。不要把链接、访问密钥或登录验证码转发给其他人，也不要粘贴到工单或公开聊天中。

## 3. 手动配置

若已经在 Relay 用户页面生成访问密钥，也可以停服后编辑：

```yaml
webshop:
  server-mode: relay
  public-url: ""

relay:
  # 留空时使用当前版本内置的官方地址
  url: ""
  access-key: "请填入用户页面生成的访问密钥"
```

保存后重启服务器。不要把真实 `access-key` 提交到 Git、面板截图或公开日志。

## 4. 账户与权益

Relay 页面可能提供注册、邮箱验证、公告、帮助、项目选择和兑换入口。页面展示的套餐、流量、请求或存储权益以当前账户页面为准；兑换前请确认选中的项目。

本文档不承诺固定的套餐数值或页面路径，以免服务调整后产生误导。

## 5. 切换回本地模式

执行 `/ws mode switch internal` 或 `/ws mode switch external`。

- `internal`：插件提供 API 与静态网页。
- `external`：插件只提供 API，网页由外部反向代理或 CDN 托管。

## 6. 排障

- **没有收到授权链接**：命令必须由游戏内管理员执行，控制台不能接收安全链接。
- **授权已过期**：重新执行 `/ws mode setup relay`，不要重复使用旧链接。
- **提示已有向导运行**：等待当前流程完成或过期后再试。
- **授权成功但页面打不开**：确认已切换为 Relay，再查看插件日志中的连接状态。
- **`/ws home` 提示未配置**：检查当前模式、连接状态和主页设置。
- **怀疑密钥泄露**：立即在用户页面撤销或更换密钥，并重新授权服务器。
