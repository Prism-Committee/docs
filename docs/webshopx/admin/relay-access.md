# Relay 公网访问

Relay 模式用于在**不直接向公网暴露 Minecraft 服务器 Web 端口**的情况下，为 WebShopX 提供可访问的公网商城入口。对于不方便配置公网 IP、端口映射、HTTPS 或反向代理的服主，这是最省维护成本的公网方案。

:::info[官方 Relay 服务]
当前官方服务面板：**[打开 WebShopX Relay 服务面板](https://47.122.127.164/)**

面板用于账号登录、项目管理、服务器绑定、兑换与用量查看。服务入口、页面布局和可用权益后续可能调整，以面板实际显示为准。
:::

本文只说明服主需要使用的公开功能和操作流程，不介绍 Relay 服务端的内部实现。

## 1. Relay 适合什么情况

推荐考虑 Relay，如果你：

- 没有固定公网 IP，或无法方便地进行端口映射；
- 希望让玩家通过统一公网地址进入 WebShopX；
- 不准备自行维护 Nginx / Caddy、HTTPS 证书和公网转发；
- 希望把公网入口和 Minecraft 服务端本身分离。

WebShopX 当前有三种 Web 运行模式：

| 模式 | Web 页面 / API | 是否需要自己提供公网入口 |
| --- | --- | --- |
| `internal` | WebShopX 插件直接提供 | 公网使用时通常需要 |
| `external` | API 由插件提供，前端外置 | 需要 |
| `relay` | 通过 Relay 提供公网访问 | 通常不需要 |

## 2. 先认识官方服务面板

打开 [WebShopX Relay 服务面板](https://47.122.127.164/) 后，普通服主主要会接触以下内容：

- **账号**：注册、登录以及账号安全相关操作；
- **项目**：一个 Relay 项目对应一个需要托管的 WebShopX 公网实例；
- **服务器绑定**：把当前 WebShopX 服务器关联到正确的项目；
- **兑换**：在获得可用兑换码时，用于开通对应项目或权益；
- **项目面板**：查看项目状态、连接情况和当前可见的使用信息；
- **用量与权益**：查看当前项目可用的流量、请求或存储等信息（具体项目以面板为准）。

:::tip
如果你第一次使用 Relay，建议**先注册/登录官方面板并确认已有可用项目**，再回游戏执行 Relay 设置命令。这样后续绑定关系更容易确认。
:::

## 3. 推荐接入流程

### 第一步：准备 Relay 账号和项目

1. 打开 [官方 Relay 服务面板](https://47.122.127.164/)；
2. 注册或登录账号；
3. 进入用户控制台；
4. 确认已有可使用的项目；
5. 如果需要通过兑换开通项目，按面板提示完成兑换。

不要在文档、工单或公开聊天中发送自己的访问密钥、授权链接或验证码。

### 第二步：从游戏内发起授权

以拥有 `webshop.admin` 权限的管理员身份进入服务器，执行：

```text
/ws mode setup relay
```

插件会返回一个可点击的安全授权链接。

1. 点击授权链接；
2. 使用你的 Relay 账号完成登录；
3. 按页面提示确认授权；
4. 回到游戏等待授权完成。

授权成功后，WebShopX 会保存当前 Relay 凭据，并提示你继续切换运行模式。通常不需要手动复制 access key。

:::warning
授权链接只应由当前服务器管理员本人打开。不要把它转发给其他玩家，也不要截图公开。
:::

### 第三步：确认服务器与项目的关系

进入 Relay 服务面板检查当前项目。

如果面板提示存在**待绑定服务器**或要求选择项目，请把当前 WebShopX 服务器关联到你准备使用的项目。多台服务器或多个项目同时存在时，应特别核对服务器和项目，不要随意绑定。

绑定完成后，项目面板应成为后续查看 Relay 状态和使用信息的主要入口。

### 第四步：切换到 Relay

回到游戏执行：

```text
/ws mode switch relay
```

然后执行：

```text
/ws home
```

如果能够打开对应项目的公网商城页面，说明基本接入已经完成。

## 4. 日常管理

Relay 接入完成后，通常在两个位置管理：

### 游戏内 / WebShopX

用于：

- 切换 WebShopX 运行模式；
- 获取当前商城入口；
- 管理 WebShopX 自身的商品、订单、市场和管理员功能。

### Relay 服务面板

用于：

- 查看和选择项目；
- 查看服务器绑定状态；
- 管理 Relay 账号相关信息；
- 查看当前项目展示的用量与权益；
- 在需要时完成兑换或项目管理操作。

Relay 面板管理的是**公网托管与项目关系**，WebShopX 后台管理的是**商城业务本身**。两者不要混淆。

## 5. 手动配置（高级）

正常使用官方 Relay 时，优先使用 `/ws mode setup relay` 完成授权。

只有在你明确知道现有访问密钥来源和目标账号时，才建议停服后手动编辑：

```yaml
webshop:
  server-mode: relay
  public-url: ""

relay:
  # 使用官方服务时通常可以保持默认/留空
  url: ""
  access-key: "请填入你自己的访问密钥"
```

保存后重启服务器。

:::danger[访问密钥属于敏感凭据]
不要把真实 `access-key` 提交到 Git、发到公开聊天、上传到工单截图，也不要让其他服务器共用来源不明的密钥。怀疑泄露时应立即在账号侧更换或撤销，并重新授权服务器。
:::

## 6. 切换回本地模式

Relay 不是不可逆操作。需要恢复本地部署时执行：

```text
/ws mode switch internal
```

或：

```text
/ws mode switch external
```

- `internal`：插件直接提供 API 与静态网页；
- `external`：插件提供 API，网页由外部反向代理或 CDN 托管。

切换前请确认新的公网入口和 `public-url` 等设置已经准备好。

## 7. 常见问题

### 没有收到授权链接

`/ws mode setup relay` 必须由拥有相应权限的**游戏内管理员**执行。控制台无法点击安全授权链接。

### 授权页面要求登录

这是正常流程。请登录你准备用于管理该 Relay 项目的账号，不要使用他人的账号替你授权。

### 授权成功但项目仍不可用

先检查 Relay 面板：

1. 是否已有有效项目；
2. 当前服务器是否仍处于待绑定状态；
3. 是否绑定到了正确项目；
4. 再确认游戏内已经执行 `/ws mode switch relay`。

### `/ws home` 提示未配置或打不开

确认：

- 当前模式确实是 `relay`；
- Relay 授权已完成；
- 面板中的项目和服务器绑定关系正确；
- 插件日志没有持续的连接错误。

### 有多台 Minecraft 服务器

不要仅凭名称猜测。分别完成授权，并在 Relay 面板核对每台服务器对应的项目关系。

### 怀疑访问密钥泄露

立即停止继续分享相关信息，在 Relay 账号侧更换或撤销相关凭据，然后重新执行授权流程。
