# 背包管理与离线安全

在线操作以服务器内真实库存为准；离线能力分为安全的只读快照和默认关闭的即时写入。

## 1. 默认行为：离线只读快照

玩家在线时，插件保存用于网页展示的库存快照。玩家离线后，网页可以继续显示最后一次快照，但禁止交易和写回。

```yaml
webshop:
  inventory-read-snapshots:
    retention-days: 30
```

快照不是权威库存，不应据此手工补发或认定物品仍然存在。

## 2. 实验性离线即时管理

后台“系统设置”中的“离线背包即时管理”允许直接读写 Minecraft `playerdata`。仅在以下条件全部满足时考虑启用：

- 单实例服务器；
- 没有跨服背包、第三方库存同步或其他直接修改 `playerdata` 的组件；
- 已备份世界与玩家数据；
- 已在相同服务端版本的测试服验证；
- 能避免玩家登录与网页写入并发发生。

## 3. 本地紧急停止开关

```yaml
safety:
  force-disable-offline-inventory-write: true
```

该开关优先于数据库和后台设置。发现复制、丢失、数据损坏风险或准备升级服务端时，应立即启用并重启服务器。

## 4. 上线与回滚检查

1. 完整备份世界目录及玩家数据。
2. 用测试账号验证背包、快捷栏、装备、副手、末影箱和容器物品。
3. 操作后重新登录，确认数量和槽位一致。
4. 验证正常关服重启和被拒绝的操作。
5. 观察业务日志，确认没有重复成交或重复扣取。
6. 出现异常时启用本地停止开关，保留日志和备份。

:::danger[不要并发写入]

玩家登录/退出、其他插件保存背包、跨服同步与 WebShopX 离线写入同时发生时，可能造成物品丢失、复制或玩家数据损坏。

:::
