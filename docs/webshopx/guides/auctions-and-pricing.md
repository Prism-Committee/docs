# 拍卖、动态定价与交易规则

这页把玩家最容易混淆的三件事放在一起：**拍卖怎么成交、价格为什么变化、为什么上架会被拒绝。**

## 1. 先判断你面对的交易类型

| 类型 | 核心特点 |
| --- | --- |
| 普通出售 | `SELL + DIRECT`，按当前价格直接成交 |
| 收购单 | `BUY + DIRECT`，卖家向买家的需求履约 |
| 拍卖 | `SELL + AUCTION`，按拍卖算法结算 |
| 动态定价 | 在部分 `DIRECT` 商品/挂单上根据供需状态调整价格 |

`BUY` 挂单不使用拍卖，也不会启用动态价格。

## 2. 四种拍卖模式

| 模式 | 怎么参与 | 结算直觉 |
| --- | --- | --- |
| 英式 `ENGLISH_AUCTION_V1` | 公开逐步加价 | 截止时最高价胜出 |
| 荷兰式 `DUTCH_AUCTION_V1` | 等价格下降后直接买断 | 第一个接受当前价的人成交 |
| Vickrey `VICKREY_AUCTION_V1` | 密封提交愿付价 | 最高出价者获胜，按次高价思想结算 |
| Candle `CANDLE_AUCTION_V1` | 公开竞价 | 结束时间带随机性，降低卡秒狙击 |

拍卖只用于 `SELL` 挂单，最短时长受服务器规则约束。出价时资金可能被临时冻结，被超价或流拍后按规则退回。

### 实用建议

- 英式：不要只盯最后一秒，末段可能触发延时；
- 荷兰式：核心是等到自己愿意接受的价格，而不是出价；
- Vickrey：更适合直接提交真实愿付上限；
- Candle：结束时间存在随机性，卡秒风险更高。

## 3. 动态价格什么时候生效

常见可用场景：

- 官方商店中的部分物品类商品；
- 玩家市场中启用了动态定价的 `SELL + DIRECT` 挂单。

通常不会用于：

- `BUY` 收购单；
- 拍卖挂单；
- 指令、药水效果、凭证等不适合动态物价的商品。

动态价格会综合基础价、需求状态和服务器设定的上下限计算。你在页面看到的算法名称，主要决定“需求变强时价格如何响应”。

### 常见算法的玩家直觉

- **线性需求**：需求越高，价格稳定上升；
- **边际递减 / 对数平滑**：前期变化明显，后续更平缓；
- **指数防护 / 恐慌抢购**：需求过强时价格加速上涨；
- **阈值分段**：达到某个需求区间后价格才明显变化；
- **弹性模型**：由弹性参数控制价格敏感度。

想研究公式和具体参数时，可继续阅读旧的深度条目：[动态价格](../player/dynamic-pricing) 与 [算法说明](../player/algorithm)。这些页面不再占主导航，但保留给高级用户。

## 4. 为什么上架会被拒绝

每次创建或修改挂单时，服务器都会重新执行交易规则检查。常见限制包括：

1. 当前物品被禁卖；
2. `BUY` / `SELL` 方向不被允许；
3. 当前交易模式不被允许；
4. 币种不被允许；
5. 标签无效或不允许；
6. 玩家缺少相应权限。

### 推荐排查顺序

1. 确认自己在创建卖单、买单还是拍卖；
2. 换成服务器常用币种；
3. 去掉自定义标签；
4. 用普通物品测试；
5. 把错误码和操作步骤一起发给管理员。

## 5. 常见错误码

| 错误码 | 含义 |
| --- | --- |
| `auction_closed` | 拍卖已结束或不可继续 |
| `bid_too_low` | 当前出价不足 |
| `auction_only_bid` | 当前拍卖只能出价 |
| `auction_only_buy` | 当前模式只能直接买断 |
| `limitation_item_forbidden` | 物品不允许交易 |
| `limitation_side_not_allowed` | 当前交易方向被限制 |
| `limitation_trade_mode_not_allowed` | 当前交易模式被限制 |
| `limitation_currency_not_allowed` | 当前币种被限制 |
| `invalid_tag` | 标签无效或未被允许 |

更完整的错误码与枚举见 [Reference](../reference/overview)。
